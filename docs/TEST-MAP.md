## Agreement with the library

- **(visual gallery)** *[visual]*  
  The grid family (a library extra beyond the web app's catalogue): five elements on a 2 x 3 array, so one cell per unit stays open — the punctured form is deliberate library behaviour (the first n cells are filled) and the openings must show as background.
- **(visual gallery)** *[visual]*  
  The stripes family (the other library extra): four parallel bands per unit.
- **UI vs library: clipped edges**  
  Clipping to the region outline, the switch whose sense is inverted on the way to the library (the checkbox says clip, the argument says ragged_edges).
- **UI vs library: dissection inner angle**  
  The two angle controls that no other test drives to an effect: a dissection's inner angle, and a star's point angle.
- **UI vs library: grid rows and columns**  
  The grid family's row and column spinners, the newest controls and the ones most likely to be mis-plumbed: a 1 x 4 array is a very different map from 2 x 2, and both carry four elements.
- **UI vs library: icons and whole-tileable join**  
  Icon mode: one unit per polygon rather than a continuous pattern, which changes the tiling call rather than the unit.
- **UI vs library: rotate/scale/skew/inset chain** *[guards]*  
  The affine chain in the order the dialog applies it: rotate, then scale, then skew, then the two insets.
- **UI vs library: slice offset, rotate, inset**  
  Family option (slice offset), rotation and tile inset together.
- **UI vs library: star point angle**  
  A star tiling's point angle: sharper points, different tiles.
- **UI vs library: weave over-under, strand width, inset**  
  Weave controls: over-under pattern and strand width, plus the subtlety that a weave's tile inset is scaled BY the strand width (insetting a weave in raw per cent of spacing would eat thin strands entirely).
- **an inset percentage is a percentage of the spacing** *[race, guards]*  
  10% at a 1000-unit spacing insets by 100 units.
- **metamorphic: full rotation and the spacing law**  
  Rotating a design by 360 degrees reproduces it; halving the spacing multiplies the tiles by about four.
- **metamorphic: translation invariance**  
  Moving the region moves the map with it, and changes nothing about its content.
- **random designs match the library**  
  Draw designs at random and require each to match the library.
- **the library works without matplotlib or scipy**  
  The vendored library must import and tile with plotting absent.
- **weavingspace unit construction**  
  The vendored weavingspace builds the units we rely on.

- **(visual gallery)** *[visual]*

- **UI vs library: categorical weave, icons, layer source** *[visual]*

- **editing a category colour reaches the map** *[visual, race, guards]*

- **element opacity (layer opacity, authority, gpkg)**

## Runs, races and concurrency

- **a finished run leaves nothing armed** *[race]*  
  When live update is off, finishing a run must not queue another.
- **a new run always shows real progress** *[race, guards]*  
  A run reports a percentage, even after one that died mid-output.
- **adversarial sequences** *[race, family]*  
  Every dangerous pairing of "start work" and "interfere with it".
- **cancelling frees the dialog at once** *[race, guards]*  
  Cancel gives the dialog back immediately, not eventually.
- **choice persistence and zombie recovery** *[race, guards]*  
  Two more state-keeping behaviours: a row's class-source choice survives a Design-tab rebuild (choices live in dicts keyed by tile id, not in the replaced widgets), and reopening the dialog recovers from a zombie task (a cancelled task left in _task must not block future runs).
- **editing colours never rebuilds the table** *[race]*  
  The chooser-race rule, applied to the new control.
- **fuzz: random interaction keeps the invariants** *[race, family]*  
  Random sequences of interaction, checked against invariants.
- **integration: cancel and recover** *[race]*  
  Cancelling a run mid-flight (what closing the dialog does) must leave the plugin able to generate again: no task stuck in _task, the Generate button enabled, and the next run completing normally.
- **integration: live update session**  
  A live-update session: switch live on, make a design change, and let the debounce fire.
- **live update gates (gpkg, comparison mode)** *[guards]*  
  Live update must decline to run when output goes to a GeoPackage (regenerating a file on every tweak would hammer the disk) and when the comparison checkbox is on (it would spawn a group per tweak).
- **live update is on by default** *[race, guards]*  
  A first map appears without anyone pressing Generate.
- **palette pick survives debounce (no chooser race)** *[race, guards]*  
  Regression for the 'race among choosers': picking a ramp must not schedule a table rebuild, so the row widgets remain the SAME objects after the debounce window and a pick made while another chooser was open can never land on a destroyed widget.
- **race: a colour picked during a run is not lost** *[race]*  
  A race: the editor is open, and the run underneath finishes.
- **race: change during the output phase** *[race]*  
  A change made while the LAYERS are being built.
- **race: close during a run** *[race]*  
  Closing the dialog mid-run must cancel cleanly: no output arriving after the dialog is gone, no wedged state, and a fresh dialog able to generate immediately afterwards.
- **race: every control changed mid-tiling** *[race]*  
  Change EACH control while a tiling is in flight, one at a time.
- **race: region layer removed during a run** *[race]*  
  The region layer disappearing mid-run must not take QGIS with it.
- **race: restyle during a run** *[race]*  
  A restyle must refuse while a tiling is in flight.
- **race: settings changed during a run** *[race, guards]*  
  Change settings while a tiling is in flight.
- **race: two Generate presses** *[race]*  
  Two Generate presses in quick succession must produce one run, then at most one rerun -- never two tilings racing each other into the same layer group.
- **run lifecycle: no overlapping runs**  
  One run at a time, including while its layers are being built.
- **stress: fast interaction (race hunt)** *[visual, race]*  
  Fast clicking, deliberately: fire the sequence of changes an impatient user makes — spacing, family, variables, ramps, styles, switches — with no pauses, while live update is ON, then let everything settle and check the plugin is coherent.
- **stress: styling, rendering and sizing on complex data** *[visual]*  
  Styling, rendering and sizing fiddled with repeatedly on the categorical fixture: spacing swept from coarse to fine and back, styles cycled through every mode, class counts changed, ramps swapped, all with generation in between.
- **the dialog's chrome does its job**  
  The parts of the window that are not the design: the region chooser's filter, the idle progress bar, and the Close button.
