ROW 1'S REPAIR HAS ONE OWNER, `topology_edits.widen_selector(selector,
glue, how)`, which takes the target from the MANIPULATION; `apply`,
the drag preview and `_refined_towards_what_was_asked` all call it,
and the dialog hands `built["glue"]` to the replay. Its lesson is the
row every hunt that reached it wrote: when a function gains a
parameter, grep its PRODUCT call sites, not its tests.

ROW 2'S HAS ONE TOO, `topology_edits.labels_in(selector, alphabet)`: a
string that is itself a label is that label, an older joined record on
a one-letter design is its characters, and a list is its members;
`move_as_applied` is the one door to the library and hands it a tuple.
A multi-class selection is now recorded as a LIST, a shape "every edge"
already wrote, so no older record changes meaning.
ITS FIRST FORM WAS INCOMPLETE, and the hunt aimed at it said so within
the hour (repairs24): a record naming `aa`, replayed on a design with no
`aa` class, was still split into `a`, `a` and moved `a`. The reading now
takes the record's own `against` -- an alphabet that held two-letter
labels named classes as labels -- and accepts a split only into DISTINCT
known labels, a repeated character with no such split being one label.
Counted as the same row, since the same user loss through the same
door; `a-record-made-against-two-letter-labels-names-one-class` stands
on it.

ROW 5'S REPAIR: `topology_edits.modified(unit, modifiers)` applies

goes on the cloth after the replay, an inset being gaps no topology can

ROW 8'S REPAIR: `_topology_stamp` carries a weave's two readings (a
tiling's stamp and saved key are unchanged), so a landing, a held dual

ROW 9'S REPAIR: `_exact_centre` answers a centrally symmetric tile with

`_consistent_centre` searches once per base tile, keyed by its shape.
