# Defects found on 2026-08-27

The 0.24.4 campaign. Six hunts were launched at once with the standing
instruction that each returning hunt is fixed and guarded before its
replacement goes out, so this ledger grows through the day rather than
being written at the end of it.

The OWES column is the honest part. `--` means the fix rests on its
hunt's own reproduction, which is not what this project calls fixed;
an entry is only finished when it names both a registered test and a
mutation-catalogue entry that has been RUN and reported `caught`.

Two of the six went to the mechanical consistency sweep rather than to
intuition, under the rule of 2026-08-26 that the sweep is proposed
beside the hunts with a reason for choosing one. The reason here is
that the ground is fresh — most of this code moved yesterday — which
the record says favours hunts; the portfolio keeps a third of the
round for the directions a sweep cannot pattern-match, and this round
inverts that deliberately to test the sweep's cost against a hunt's on
ground where hunts are supposed to do well.

## What the round has taught so far

**A GUARD WHOSE CONDITION IS RIGHT CAN STILL BE AIMED AT NOTHING.**
Row 4's guard reads `_fieldless_build`, and that flag was measured
True at exactly the moment the defect fires. Its first test passed
anyway with the guard mutated away, because the journey it drove — a
recolour to a SINGLE SYMBOL — never reaches the adoption that queues
the restamp at all. A single symbol is deliberately not followed (the
scope of the follow ruling of 2026-08-17), so the test was aimed at a
door the act never opens. What found it was the catalogue, not
reading, and the repair was to drive the recolour the way this suite's
other adoption tests drive it: clone the renderer the layer already
has, move one class's colour, install the clone.

**AND THE PREMISE CHECK LIED FIRST.** The rewritten test then failed
on its own premise, because that check read
`layer.renderer().ranges()[0].symbol()` — the freed-temporary pattern
this project has already paid for twice. A premise that cannot be
trusted is worse than no premise, since its failure is read as the
product's. Bind the list to a name before subscripting it, in tests as
much as in the plugin.

**A REPAIR AIMED AT AN ACT MUST BE RE-AIMED AT THE ACT'S ABSENCE.**
Rows 5 and 6 are one sentence apart. On 2026-08-26 the stale-table
drop was taught to take the saved style with the table, which mends
every case where something is deleted. Both of these are cases where
nothing is deleted at all: once because the record of what to delete
lives on a window rather than in the file, once because the table name
did not change and so nothing looked stale. Two hunts found them from
different directions on the same afternoon, which is what makes the
shape worth naming rather than the two rows.

**AND THE INSTRUMENT CHANGED WHAT IT MEASURED, TWICE IN ONE TEST.**
Row 5's guard first read the file through a `QgsVectorLayer` it left
alive, and the open handle made the NEXT run fail at the sqlite level:
zero tables, read as the product's fault. Row 6's guard then read the
file's raw bytes while the dataset was still open and found the
abandoned colour sitting in sqlite's freelist — present with the layer
open, absent once everything had let go, with the style row itself
gone in both readings. The file a colleague receives is the file after
it is closed, and that is the only moment a byte-level claim about it
means anything.

**AND THE SWEEP THAT FINDS A FAMILY MUST SWEEP FOR THE QUESTION.**
Row 3 is the ninth `same_source` site, and it survived the eight-site
sweep of 2026-08-26 for the reason the eighth did: the sweep searched
for the SHAPE that had just been fixed. Eight compared a stamp with a
stamp; the eighth compared a stamp with a live source; this one
compares a layer source with a bare path. Three different pairs of
operands asking one question. The lesson was already written down
after the eighth and it did not prevent the ninth, which suggests the
remedy is not another sentence but a check: anything comparing two
strings either of which has been through a filesystem is a candidate,
and that is greppable.
