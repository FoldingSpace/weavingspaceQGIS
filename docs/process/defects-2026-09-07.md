## Row 1, in full, because the shape is the transferable part

C-341 reformulated `rotate_edge` and `scale_edge` to move each shared
vertex once, so the tiling stays edge-to-edge where the library's
per-edge versions tear it. That reformulation was written into `apply`
and into `apply` alone. It had THREE callers who must agree with it:
the drop, the drag PREVIEW, and `lays_out`, which is the predicate
every zigzag ceiling is found with.

MEASURED, `laves 3.3.4.3.4` class `a`, one fundamental cell:

    edit                    the preview drew        the drop records
    rotate_edge  15 deg     gap 1.7785% ovl 0.222%  gap 0% ovl 0%
    rotate_edge  60 deg     RAISED GEOSException    gap 0% ovl 0%
    scale_edge   sf 1.5     gap 0.8911% ovl 8.216%  gap 0% ovl 0%
    zigzag_edge  (CONTROL)  gap 0%      ovl 0%      gap 0% ovl 0%

THE CONTROL ROW IS WHAT MAKES THE OTHERS READABLE: zigzag is not
rerouted, so both routes are the same call and must agree — and they
do. A uniform verdict would have been the instrument.

THE REPAIR IS ONE OWNER, `topology_edits.move_as_applied`, which
performs the move a commit would perform; `apply`, `lays_out` and the
drag preview all go through it. The alternative — copying the dispatch
into the tab — is the state the code was already in, one site short.

AND `lays_out` CARRIED A FALSE CLAIM while this stood: its docstring
said it asks "through the same two steps `apply` uses ... so the two
cannot disagree", which was true of zigzag and false of rotate and
scale. Only `zigzag_ceiling` calls it today, so the harm was latent;
it is true now rather than merely written.

THE LESSON, and the hunt that found it said it best: when a
reformulation reroutes a library call, the CALLERS are the door list —
grep for the library's symbol, not for the reformulation's name.

## Row 1 closed a SECOND claim, which was checked rather than assumed

Hunt `preview` reported, separately, that a torn preview stops saying
so the moment the value freezes: the held arm of `_on_dragging` writes
`failed` as "nothing has laid out yet in this gesture" and discards
what `_status_of_a_drag` decides from `plane_coverage`, so red turns
amber while the same torn design is still on screen. It measured that
on a per-edge rotate of `archimedean 4.8.8` — which is the route row 1
removed.

MEASURED ON THE REPAIRED TREE, and the design the claim was made on is
in the sweep because a negative that omits it is not a negative: 155
combinations of design, class, manipulation and value across `laves
3.3.4.3.4`, `hex-slice 3` and `archimedean 4.8.8` produced NO move
that lays out and still tears. The held arm's own comment reserves
FAILED for exactly that state, so with the per-edge route gone there
is nothing left to reach it.

SO THE CLAIM WAS REAL BEFORE `a2f719a` AND IS INERT AFTER IT. What
survives is a LATENT disagreement rather than a live defect: the held
arm still invents its two flags instead of asking the twin that owns
the judgement, and the day something drawable can tear again, the two
will disagree. Recorded here rather than repaired, because a guard for
it would have to stage a state no geometry currently produces.

(A fixture trap on the way, worth the line: my first sweep asked for
`archimedean 4.8.8` at n=3 and got a KeyError it reported as "could
not build", so the claim's own design was silently absent from the
first negative. A FAMILY TYPED IS NOT A FAMILY CHOSEN — look the name
up in the catalogue, which is the third time this document's family
has recorded that.)

## Corrected rather than counted: a comment that promised what the code cannot do

Hunt `clamp` found that `_on_dragging` justified computing no ceiling
during a drag by saying "the COMMIT-time clamp then applies the true
ceiling at the drop, so a fast drag that stops a little short is
corrected on release". It cannot: `apply`'s clamp is entered only
where the edit produced nothing drawable, and a held value laid out by
construction, so the clamp only ever LOWERS. Measured: asked h=0.297
against a ceiling of 0.594, `apply` returns 0.297 untouched.

AND THE SHORTFALL IS A FRAME OF TRAVEL, NOT A PIXEL OF IT, which is
what decides whether this is a wrong comment or a defect: a frame
costs 158 ms and the default design's edges draw at about 94 px, so a
pointer at 250 px/s advances 0.42 of the amplitude between samples
against that 0.594 ceiling.

The comment is corrected. The BEHAVIOUR is ruling 2 working as
written — the value holds at the last one that laid out — so making
the drop seek the exact ceiling is a change to a ruling rather than a
repair, and it is the maintainer's to make. Not counted among the
twelve: no code changed.
