about=Creates tiled and woven map layers that carry several attributes
    of a polygon dataset in a single map, using the weavingspace library
    by David O'Sullivan and Luke Bergmann (bundled, MIT licensed).
    Choose a tiling or weave design, assign a variable and colour ramp
    to each pattern element, and the plugin adds a group of ordinary
    QGIS layers seeded with standard renderers, ready for the usual
    styling tools. The method is described in O'Sullivan and Bergmann
    (2026), Cartographic Perspectives 108. This is an experimental
    prototype, mostly co-written by Luke Bergmann with large language
    models. Requires QGIS 4 or later. It needs geopandas, pandas, and
    shapely, which most QGIS 4 installations already include; where
    they are missing or too old (most often on Linux, where QGIS uses
    the system Python), the plugin shows exactly what it would fetch
    and asks first; approving downloads those wheels from PyPI into
    the plugin's own folder, changing nothing else in your QGIS
    installation, and declining simply closes the plugin. Released
    under the MIT licence; the bundled weavingspace library is MIT
    too, and both notices are in LICENSE.md.

changelog=0.24.3 A colour can now mean the same thing everywhere it
    appears on the map, if that is what you want, and you can set the
    class bounds yourself where the automatic ones do not suit.
    Class bounds: pin the first or last class in the colour editor and
    type its inner bound, and the classes between are recomputed
    around it. Unpin and that break goes back to being worked out for
    you. Bounds that cannot be drawn are refused and the reason said,
    rather than quietly turned into different numbers.
    Copying: send one element's classes, colours, pins and class count
    to another from the same window. Where the two carry different
    columns the ends are fitted to the receiving data, and any class
    its values cannot reach is hatched in the swatch so an empty class
    is visible.
    Colour: an element is now classed from the whole map's values
    rather than from its own tiles alone, so two elements you have set
    up alike can be read against each other. They could not before:
    the same shade stood for different numbers in different parts of
    the pattern.
    Classes: a column with fewer values than the classes you asked
    for now draws the classes it has, and says so, instead of putting
    swatches in the legend that no tile uses.
    Reopening a project: an element whose ramp you reversed comes
    back reversed, naming the ramp you chose rather than reading as
    custom colours.
    0.24.2 Bugfixes, one of them about not losing data.
    Your files: an existing .gpkg chosen as the output was rewritten
    whole, so every other table in it was lost, including the layer
    you were tiling if it lived there. Only the tables this plugin
    wrote are replaced now. Nothing else is touched. True since
    0.23.0, so upgrade before generating into a file you keep other
    work in.
    Colour: a ramp the dropdown offers is now the ramp you get, and a
    colour picked by hand survives a run landing, a lost column and a
    reopened project. What the plugin says it discarded stays
    discarded. Categorized layers record their ramp, so QGIS's own
    panel shows it and Classify starts from the right place.
    Class colour files: edit a .qml and Generate draws what it says
    today. Move one and the element keeps its colours, with the
    missing file named.
    Reopening a project: an element's ramp and class count come back
    from the layer rather than from a default. Reverse does not yet.
    Alongside QGIS: Classify no longer fails on a one-value column, a
    closed dialog no longer writes layers into your project, and an
    emptied region layer is reported rather than quietly stopping the
    plugin.
    Live update: a run that cannot finish says so on the note line
    instead of interrupting you with a message box.
    Correction: that live-update change reached you in 0.24.1, whose
    notes wrongly said nothing else had changed.
    0.24.1 Setting the plugin up is more forgiving where QGIS does not
    already carry the packages it needs, which mostly means Linux.
    Setup: when one of them cannot be downloaded the plugin says which
    package and what went wrong, rather than only that something is
    missing. It tries again once when the network was at fault, and it
    has a second version to fall back on.
    0.24.0 The map follows the layer, and data that does not suit a
    style is drawn sensibly rather than drawn wrongly.
    Following the layer: editing, deleting or reprojecting features in
    QGIS updates the map rather than leaving it out of date, and a
    column added there can be mapped straight away.
    Awkward data: areas with no value are left out of the class breaks
    and counted in a notice; a column with one value draws as one
    class; choosing a quantitative style for a column of text draws
    categories rather than nothing.
    Colour: an Edit colours button sets a colour per value for
    categorical elements.
    Warnings: you are told when a spacing leaves areas off the map,
    when a changed category count moves existing colours, and when two
    elements' colours are hard to tell apart.
    Preview: it shows one ring of neighbouring tiles by default, and
    colour-ramp swatches are larger.
    0.23.0 Per-element control over colour, two new pattern families,
    and a public home for the project.
    Data table: reverse-ramp switches and per-element opacity.
    Patterns: grid and stripe families, with their own row and column
    controls.
    Project: published as a public repository with a project page.
